# NLP 测试指令编写规范

## 一、基本结构：登录归登录，业务归业务

- **登录步骤不要在 NLP 里写**：由创建页"登录方式"区块负责（免登录填目标网址；CAS/本地登录选账号）。系统生成脚本时会自动把登录 NLP 拼在前面。
- **NLP 只写登录后的业务步骤**，提示语范式：`登录后的步骤：输入xxx，点击xxx，验证xxx`。

## 二、步骤写法（AI 可执行的标准句式）

每行一个动作，动宾结构，目标元素具体：

```
✅ 好的写法
在搜索框输入"Headphones"
点击搜索按钮
验证页面出现"Headphones"相关结果
等待页面加载完成

❌ 差的写法
搜索一下耳机            ← 动作不明确，没有具体输入值
检查是否正常            ← 断言目标缺失
点那个按钮              ← 元素指代不明
```

- 输入值用引号包裹：`输入"admin"`；
- 断言写清期望：`验证页面显示"登录成功"` / `验证文件里有"20300"`；
- 等待写清条件：`等待"订单列表"出现`。

## 三、动态值与 [动态] 标记

每次执行值都会变化的内容，必须用 `[动态]` 前缀标记（→ 该步骤 `cacheable: false`，不走缓存）：

```
[动态] 识别图形验证码并填入
[动态] 获取短信验证码并填入
[动态] 输入今天的日期
```

预置动态值类型（登录方式补充步骤下拉框）：图形验证码 / 短信验证码 / 滑块验证 / 邮件验证码 / 自定义。

**判断准则**：这一步的内容这次执行和下次执行是否完全一样？一样→不标记；不一样→`[动态]`。固定账号密码、固定菜单名、固定按钮**不是**动态值。

## 四、NLP → YAML 映射（理解生成结果）

| NLP 特征 | 生成 YAML |
|---|---|
| 登录步骤（打开登录页/输账号密码/点登录） | 独立 `name: 登录` task |
| `[动态]` 步骤 | 步骤上加 `cacheable: false` |
| 验证/断言句 | `aiAssert`（天然不缓存） |
| 含 URL | `web.url` 字段 |

## 五、复合指令（插件场景）

- "点击下载，断言文件里有X"：插件会先执行下载动作、等文件落地、再断言文件内容，单句可完成；
- 但平台用例中建议拆两行（下载一行、断言一行），可读性与缓存粒度更好。

## 六、标准化纠错示例

| 用户输入 | 标准化后 |
|---|---|
| 登录系统然后查看订单 | （登录方式区块处理）+ `点击"订单管理"菜单` + `验证订单列表已显示` |
| 输入验证码 | `[动态] 识别图形验证码并填入` |
| 下载报表看看对不对 | `点击"下载报表"按钮` + `断言下载的文件内容包含"<关键字段>"` |
