## 1. 项目核心初衷

### 1.1 现存痛点

传统 UI 自动化方案高度依赖纯多模态视觉能力落地，整体落地门槛高、实施成本居高不下：

- **适配成本高**：页面样式、布局、环境存在各类细微差异，需投入大量人力进行专项适配、脚本编写与后期维护，单场景自动化落地周期长
- **算力开销大**：纯多模态大模型推理存在算力消耗大、执行效率偏低的问题，在金融大批量回归测试、日常巡检、业务流程校验场景下，性能瓶颈与成本浪费被持续放大

### 1.2 核心价值：降本提效

项目核心遵循 **"单个 case 微小提升，批量场景大幅提升"** 的思路，深度适配生产流程：

- **降低成本**：摒弃传统纯多模态高成本实施方案，通过 NLP + 多模态视觉融合方案，屏蔽多环境、多页面的差异性，大幅降低脚本编写、适配迭代、日常维护的人力成本；同时通过缓存优化机制，解决大模型高算力消耗问题，有效压降算力资源成本
- **提升效率**：单条自动化用例的编写、推理、执行效率实现小幅优化，在大量业务流程、批量回归、常态化巡检的生产场景中，规模化复用后形成量级效率提升

### 1.3 价值视角

| 层面 | 价值 |
|------|------|
| **个人** | 消除重复适配、重复编码，降低 UI 自动化上手门槛，减少人工纠错、页面调试的重复工作量 |
| **小组** | 缩短自动化脚本交付、问题排查、版本迭代周期，统一开发调试标准，提升团队整体交付产能 |
| **部门** | 搭建标准化、可规模化复用的智能 UI 自动化体系，实现全流程降本提效，完善自动化基建能力 |

## 2. 核心功能

### 2.1 自然语言驱动测试用例生成

- **NLP 智能生成**：手动输入自然语言测试步骤，系统自动拆解为精确操作类型并生成 YAML 脚本
- **YAML 编辑器**：内置 CodeMirror 编辑器 + 表单编辑器，支持手动修改和双向同步
- **零代码编写**：测试人员无需编程基础，用大白话描述即可

### 2.2 测试用例管理与执行

- **用例 CRUD**：按项目分组管理，支持权限过滤、批量删除
- **单条执行**：用例管理页面一键执行已有用例
- **批量执行**：同一项目下多用例一键批量执行
- **缓存优先 + AI 兜底**：再次运行已执行的用例时，优先使用缓存结果；缓存失败自动切换 AI 视觉识别，平衡性能与准确性

### 2.3 测试计划管理

- 将多个用例打包为**测试计划**，统一管理
- 计划内可新增或删除用例，双列卡片式选择器自动去重
- 按 sort_order 串行执行计划内所有用例
- 支持 ACTIVE / ARCHIVED 状态管理

### 2.4 数据看板

- 全局统计卡片：总项目数、总用例数、执行成功/失败数
- 执行结果柱状图 + 近 7 日趋势折线图
- 各项目成功率对比表（绿色 ≥ 80%、红色 < 50%、黄色居间）
- 告警阈值可配置

### 2.5 AI 配置

- 支持 OpenAI / Claude / Gemini 等多种模型家族
- 可自定义 Base URL、API Key、模型名称
- 浏览器模式切换：Headless（无头/后台运行）vs Headful（可视化/可观察）
- API Key 自动脱敏，安全性保障

### 2.6 Chrome 浏览器插件

- **启动认证**：登录后自动获取有权限的项目列表，支持新建项目；创建者自动获得权限
- **逐步执行**：AI 将自然语言拆解为精确操作步骤（点击/输入/断言/等待/滚动），逐条执行并标记结果
- **智能导出**：默认排除执行失败的步骤，用户可手动勾选；一键合成测试用例并推送到中台
- **权限控制**：sysadmin 拥有最高权限管理所有项目

### 2.7 用户与权限

- JWT 登录认证，BCrypt 密码加密
- 角色体系：**系统管理员（sysadmin）** vs **普通用户（general）**
- 用户管理（管理员专属）：创建/编辑/删除用户、重置密码
- **项目级权限控制** — 管理员可为每个用户分配可访问的项目

**第一步：启动前端**


```powershell

$env:PLAYWRIGHT_BROWSERS_PATH="D:\playwright-browsers"
```

## 5. 核心技术选型

| 技术 | 选型原因 |
|------|----------|
| **Docker 容器化** | 实现全流程运行环境标准化，屏蔽多环境依赖差异；支持一键部署、批量分发 |
| **NLP + 多模态视觉融合** | 替代传统纯多模态方案，通过自然语言驱动自动化，自动屏蔽 UI 页面差异性；配套缓存机制优化推理效率 |
| **Spring Cloud 微服务** | 业务逻辑与执行引擎解耦，支持独立部署和弹性扩展 |
| **Playwright + AI Agent** | 通过截图分析定位元素，不依赖 DOM 选择器，页面变化自动适应 |
| **CodeBuddy + Git AI 双 AI 交叉赋能** | CodeBuddy 负责脚本智能生成、代码纠错；Git AI 负责版本智能校验、变更追溯；形成生成-校验-优化-管控闭环 |

## 7. AI 辅助开发体系

### 7.1 三层 Skill 体系

本项目建立了完整的三层 AI Skill 体系，覆盖从需求分析到代码实现的全流程：

| 层级 | Skill | 使用场景 |
|------|-------|----------|
| **需求分析** | product-management-workflows, feature-spec, user-research-synthesis, metrics-tracking | 产品需求探索、PRD 编写、用户反馈分析 |
| **规范驱动(SDD)** | openspec-propose, openspec-explore, openspec-apply-change, openspec-archive-change | 变更提案生成、根因分析、逐步实现、归档管理 |
| **功能开发** | element-plus-vue3, java-springboot, spring-cloud, express, frontend-design | 前端组件、后端开发、微服务、执行引擎 |

### 7.2 编码规范

- **分层约束**：Controller 仅负责请求校验和响应，禁止写业务逻辑或 SQL；Service 必须定义接口+实现类
- **数据模型**：Entity 仅用于 ORM 映射，DTO 用于 API 出入参；严禁直接将 Entity 作为 API 返回值
- **参数校验**：Controller 入参 DTO 必须使用 @Valid/@Validated；字段添加 @NotBlank、@Size 等约束注解
- **SQL 规范**：简单 CRUD 使用 MyBatis-Plus LambdaQueryWrapper；禁止 Java 代码中拼接 SQL 字符串
- **敏感信息**：严禁硬编码密码、Token、IP 地址，必须存放在 application.yml 或环境变量中
- **命名风格**：驼峰命名法；强制使用 try-catch 处理异步操作；代码超过 20 行考虑聚合
- **测试规范**：Service 测试使用 JUnit 5 + Mockito Mock Mapper；Controller 测试使用 @WebMvcTest + MockMvc

### 7.3 Agent 协作规则

- **最小接口原则**：创建新接口或功能时，严格遵循已有架构，以最少代码实现目标
- **全链路追踪**：任何 Bug 修复前必须通过 OpenSpec Explore 完整追踪调用链路
- **决策记录**：所有重大技术决策记录在 design.md，包含方案对比和选择理由
- **进度可视**：tasks.md 的 checkbox 机制实现 14 个变更提案的任务追踪
