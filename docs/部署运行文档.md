# 部署运行文档

本文档按照当前仓库中的 `Dockerfile`、`docker-compose`、前端代理和后端配置说明部署方式。

## 1. 环境要求

- JDK 11
- Maven 3.8+
- Node.js 18+
- pnpm
- Docker
- MySQL 8.0
- Redis 6+
- Chrome / Chromium
- 可选：Kafka、SkyWalking

## 2. 服务组成

- `eureka-server`：注册中心，端口 `8761`
- `gateway-service`：统一网关，端口 `8080`
- `platform-service`：业务后端，端口 `8081`
- `execute-service`：执行引擎，默认端口 `3001`
- `frontend`：Vue3 前端，开发端口 `3000`

## 3. 目录与镜像

### 前端

- 源码目录：`frontend`
- 构建后输出：`frontend/dist`
- 容器镜像：`stp-frontend:latest`
- 容器内通过 Nginx 提供静态资源，并把 `/api`、`/execute`、`/reports` 转发到后端网关

### 后端

- 根工程为 Maven 多模块项目，子模块包括 `eureka-server`、`gateway-service`、`platform-service`
- 网关和业务服务都基于 Java 11 镜像运行
- `gateway-service` 和 `platform-service` 都内置了 SkyWalking agent 目录

### 执行服务

- 源码目录：`execute-service`
- 使用 `tsx` 开发模式或 `tsc + node` 生产模式
- 默认监听 `3001`
- 提供 `/execute/sync`、`/execute/async`、`/execute/:id/status`、`/execute/:id/cancel`、`/sse/progress`、`/ws/progress`

## 4. 构建步骤

### 4.1 前端

```bash
cd frontend
pnpm install
pnpm run build
```

构建完成后会生成 `frontend/dist`，这是前端 Docker 镜像直接使用的静态资源目录。

### 4.2 后端

在仓库根目录构建父工程：

```bash
cd backend
mvn -DskipTests package
```

构建后各模块的 jar 包位于对应的 `target` 目录。

### 4.3 执行服务

```bash
cd execute-service
pnpm install
npm run build
```

## 5. 配置说明

### 5.1 前端代理

开发环境下，`frontend/vite.config.ts` 将以下路径代理到网关：

- `/api` -> `http://localhost:8080`
- `/execute` -> `http://localhost:8080`
- `/reports` -> `http://localhost:8080`

生产环境下，`frontend/nginx.conf.template` 通过 `BACKEND_GATEWAY_URL` 注入后端网关地址。

### 5.2 后端关键环境变量

`platform-service` 至少需要：

- `SPRING_DATASOURCE_URL`
- `SPRING_DATASOURCE_USERNAME`
- `SPRING_DATASOURCE_PASSWORD`
- `EUREKA_CLIENT_SERVICEURL_DEFAULTZONE`
- `JWT_SECRET`
- `REPORT_UPLOAD_TOKEN`

`gateway-service` 常用：

- `EUREKA_CLIENT_SERVICEURL_DEFAULTZONE`
- `EXECUTE_HOST`
- `EXECUTE_PORT`
- `GATEWAY_CORS_ALLOWED_ORIGINS`

`execute-service` 常用：

- `PORT`
- `QUEUE_TYPE`
- `REDIS_URL`
- `REPORT_UPLOAD_TOKEN`
- `PLATFORM_REPORT_UPLOAD_URL`
- `PLATFORM_REPORT_PUBLIC_BASE_URL`
- `MIDSCENE_MODEL_BASE_URL`
- `MIDSCENE_MODEL_API_KEY`

## 6. 本地启动顺序

建议按以下顺序启动：

1. MySQL、Redis、可选 Kafka
2. Eureka Server
3. Platform Service
4. Gateway Service
5. Execute Service
6. Frontend

### 6.1 启动注册中心

```bash
cd backend
mvn -pl eureka-server -am spring-boot:run
```

### 6.2 启动业务后端

```bash
cd backend
mvn -pl platform-service -am spring-boot:run
```

### 6.3 启动网关

```bash
cd backend
mvn -pl gateway-service -am spring-boot:run
```

### 6.4 启动执行服务

`execute-service/.env.example` 中默认 `PORT=3000`，但源码默认端口是 `3001`。建议显式改成：

```bash
cd execute-service
pnpm install
$env:PORT="3001"
pnpm run dev
```

或者生产模式：

```bash
cd execute-service
$env:PORT="3001"
pnpm run build
pnpm start
```

### 6.5 启动前端

```bash
cd frontend
pnpm install
pnpm run dev
```

默认访问地址：

- 前端：`http://localhost:3000`
- 网关：`http://localhost:8080`
- 平台服务：`http://localhost:8081`
- 注册中心：`http://localhost:8761`
- 执行服务：`http://localhost:3001`

## 7. Docker 部署

仓库当前没有一个统一的顶层 `docker-compose.yml`，而是按服务拆分了 Dockerfile 和 compose 文件。可按下面步骤部署。

### 7.1 构建镜像

```bash
cd frontend
pnpm install
pnpm run build
docker build -t stp-frontend:latest .

cd ..\backend
mvn -DskipTests package

cd eureka-server
docker build -t stp-eureka:latest .

cd ..\gateway-service
docker build -t stp-gateway:latest .

cd ..\platform-service
docker build -t stp-platform:latest .
```

### 7.2 启动容器

#### 前端

`frontend/docker-compose-frontend.yml` 使用 `host` 网络，并通过 `BACKEND_GATEWAY_URL=http://localhost:8080` 指向网关。

#### 网关

`backend/gateway-service/docker-compose-gateway.yml` 同样使用 `host` 网络，默认依赖：

- Eureka：`http://localhost:8761/eureka/`
- 执行服务：`localhost:3001`
- SkyWalking Collector：`127.0.0.1:11800`

#### 平台服务

`backend/platform-service/docker-compose-platform.yml` 使用 `host` 网络，默认依赖：

- MySQL：`localhost:3306`
- Eureka：`http://localhost:8761/eureka/`
- JWT 和报告上传 token
- SkyWalking Collector：`127.0.0.1:11800`

### 7.3 运行顺序

建议先启动：

1. MySQL、Redis、Kafka（如启用）
2. `stp-eureka`
3. `stp-platform`
4. `stp-gateway`
5. `execute-service`
6. `stp-frontend`

## 8. 初始化数据库

平台服务的 SQL 初始化脚本和迁移脚本位于：

- `backend/platform-service/src/main/resources/sql/init.sql`
- `backend/platform-service/src/main/resources/sql/V*.sql`

首次部署时，先创建数据库 `uitest`，再执行初始化脚本和迁移脚本。

## 9. 验证方式

- 前端能打开并登录
- 网关 `/api/platform/**` 能返回业务接口
- 平台服务 `/doc.html` 可访问接口文档
- 执行服务 `/health` 返回正常
- 执行一条用例后能在报告中心看到结果

## 10. 常见注意项

- `execute-service` 默认端口是 `3001`，不要直接沿用 `\.env.example` 的 `3000`。
- `platform-service` 运行前必须准备好 MySQL。
- 如果启用链路分析，需要配置 SkyWalking Collector 和项目级 `skywalking_graphql_url`。
- 如果启用 API 交换采集，需要配置 Kafka。
