# 智能测试中台（STP）培训材料

> —— 基于 Midscene 的自然语言驱动 UI 自动化测试平台
> 面向对象：内部测试人员 | 时长建议：60~90 分钟（含现场演示）

---

## 一、为什么我们要换一种做 UI 自动化的方式

先回顾一下传统 UI 自动化的日常痛点：

| 传统方式（选择器驱动） | 痛在哪 |
|---|---|
| 写用例前先 F12 抓 CSS / XPath | 门槛高，测试人员要懂前端结构 |
| 元素一改版，选择器批量失效 | 用例维护成本永远追不上版本迭代速度 |
| 断言写的是 DOM 内部状态 | "测过了"不等于"用户看到的对了" |
| iframe、canvas、动态渲染页面 | 选择器方案基本无解或极其繁琐 |
| 一条回归几百条用例 | 没人愿意写，写完也没时间维护 |

**Midscene 的回答是：让 AI 像人一样"看"页面，测试人员用中文描述意图就够了。**

---

## 二、Midscene 是什么（官方背景）

[Midscene.js](https://midscenejs.com/zh/) 是一个**基于视觉的 GUI Agent 与自然语言 E2E 测试框架**，开源（GitHub 15k+ stars，曾登 GitHub 趋势榜第 2），字节跳动、阿里巴巴、携程、小米、B 站、飞书、抖音等均在生产使用。

### 2.1 核心理念："像人一样看懂界面，用自然语言完成 E2E 测试"

它的工作方式模拟真实用户：

1. **观察屏幕** —— 通过读取界面**截图**来理解页面，**不依赖 DOM 结构**；
2. **执行操作** —— 在视觉上找到目标元素，进行点击、输入或滚动；
3. **检查结果** —— 断言**用户实际看到的内容**（而非内部 DOM 状态）。

因为不依赖渲染结构，同一套 API 可跨 Web / Android / iOS / HarmonyOS / 桌面 / canvas 复用——iframe 和 canvas 页面对视觉方案不再是禁区。

### 2.2 三个核心 API（记住这三个就够了）

| API | 人话 | 例子 |
|---|---|---|
| **aiAct** | "去做这件事" | 搜索耳机，然后筛选价格低于 100 的结果 |
| **aiAssert** | "检查你看到的是不是这样" | 搜索结果中有商品，且每件价格都低于 100 |
| **aiWaitFor** | "等到这个状态出现再继续" | 等筛选后的结果已展示 |

对比传统方式：不再写 `page.locator('#submit-btn')`，而是写 `aiTap: 提交按钮`。

### 2.3 官方实测效果

- AndroidWorld 基准 Pass@1 **93.1%**；AppControlBench Pass@1 **96.7%**（60 项任务，模型调用总费用约 **$0.59**）——又准又便宜；
- **缓存机制**：AI 规划与元素定位结果可缓存重放，官方示例执行耗时从 **51 秒降到 28 秒**（这一点我们的平台做了深度增强，见第四节）。

### 2.4 一句话总结

> Midscene 提供了"AI 看懂页面并执行操作"的引擎；而我们的智能测试中台，是把这个引擎包装成**不开代码、不碰命令行**的企业级测试工作台。

## 三、我们平台的整体架构（一图看懂）

```
你写中文用例 ──► 前端工作台(:3000) ──► 后端平台(:8081)
                                          │  NLP标准化 / YAML生成 / 登录方式管理 / 调度
                                          ▼
                                    执行引擎(:3001)
                                    Node + Playwright + Midscene
                                    队列 + Worker池并发 + 缓存 + 报告生成
                                          │
                ┌─────────────────────────┼──────────────────────────┐
                ▼                         ▼                          ▼
        Midscene HTML 视觉报告      登录缓存回传平台          API报文→Kafka→SkyWalking
        (步骤级截图+Agent回放)      (uncached→cached)         (链路染色+Trace拓扑)
```

另有一位"外挂"：**Chrome 测试用例可视化插件**——直接在你的真实浏览器里跑 AI、录步骤、一键回传平台。

平台核心理念（README 原话）：**"单个 case 微小提升，批量场景大幅提升"**——低代码、低成本、高效率。

执行机地址支持"用户级 > 项目级"两级配置，未来可弹性扩展多台执行机并行跑量。

## 四、特色功能详解（本次培训重点）

### 4.1 中文大白话直接写用例 ⭐ 零代码门槛

你只需要这样描述：

```
打开 http://xxx 系统，输入用户名 admin，点击查询按钮，
断言页面展示了查询结果列表，等待导出按钮出现
```

平台自动完成"三段加工"：

**① NLP 标准化** —— AI 把口语化描述改写成标准分步列表（每行一个动作），模糊指代自动推断为具体元素名；AI 不可用时自动降级为本地规则拆分，不耽误干活。

**② AI 流式生成 YAML 脚本** —— 前端有专门的"AI 思考 + 脚本生成"双流窗口，你可以**看着 AI 的思考过程逐字生成脚本**，温度参数 0.1 保证输出稳定。

**③ 执行引擎行级执行** —— 每行自然语言通过 Midscene 视觉驱动逐步执行。

> 演示要点：现场输入一段口语化步骤，让观众看 SSE 流式生成过程。

### 4.2 YAML 脚本模式：进阶用户的精确控制

点开"生成脚本"就能看到 AI 产出的 YAML（也是可手动编辑的格式）：

```yaml
web:
  url: https://xxx
  timeout: 600000
tasks:
  - name: 登录            # 登录必须独立成 task
    flow:
      - aiInput: 'admin'
        locate: 账号输入框
      - aiInput: '密码123'
        locate: 密码输入框
      - aiAct: '识别图形验证码并填入'
        cacheable: false          # 动态步骤禁用缓存！
      - aiWaitFor: '登录已完成，页面已进入主界面'
  - name: 业务查询
    flow:
      - aiTap: 查询按钮
      - aiAssert: 页面展示查询结果列表
      - downloadFile: 下载报表按钮
      - assertFile: 报表.csv
        contains: 关键统计数字
```

平台特色：

- **双编辑器双向同步**：表单编辑器和 YAML 代码编辑器（CodeMirror）改哪边另一边自动同步；最终脚本预览与真实执行走同一条组装代码路径，**预览即执行所见**；
- **自定义文件操作三兄弟**（官方 Midscene 没有的扩展）：
  - `uploadFile` 上传本地文件；
  - `downloadFile` 捕获下载并保存；
  - `assertFile` 校验文件内容——**确定性文本包含检查优先，AI 语义断言兜底**，docx/xlsx 都能解出文本来查；
- 内建 YAML 校验器，下发前拦截格式错误。

### 4.3 登录一次、全项目复用 ⭐⭐ 本平台最特色的工程设计

传统自动化最浪费时间的环节就是：**每条用例都要重新登录一遍**。本平台的解法：

- **三种登录方式类型**：免登录（none）/ CAS 单点（cas）/ 本地账号（local），按项目统一配置、按用例引用；
- **独立登录缓存**：登录阶段以独立缓存 ID `login_{methodId}` 执行——首次真实登录成功后，AI 的规划结果被缓存；**同一账号之后项目内所有用例直接重放登录缓存**，浏览器不中断，登录完无缝接着跑业务步骤；
- **缓存状态可视**：登录方式带 `uncached / cached` 状态标记，首次执行成功后执行引擎**自动回调平台**更新为 cached，前端一目了然；
- **变更自动失效**：登录地址 / 账号 / 密码 / 补充步骤任何一项被修改，缓存状态自动重置回 uncached，下次执行重新登录重建缓存——不脏读、不漏更新；
- **登录与业务彻底解耦**：
  - 执行已有用例时平台自动注入登录方式，同时**自动剥离用例里残留的登录步骤**（NLP 模式剥前缀、YAML 模式剔除「登录」task），防止重复登录；
  - 业务页面与登录页相同时自动跳过重复导航，防止执行中"跳回登录页"。

> 现场演示要点：跑同一条用例两次，对比第二次登录阶段的耗时。

### 4.4 缓存优先、AI 兜底、动态内容精确禁缓存 ⭐⭐ 又快又准又省钱

Midscene 官方缓存机制（AI 规划 + 元素定位缓存，官方数据 51s→28s）在平台中被做成三层增强：

1. **缓存优先**：执行前平台把 DB 中的缓存内容写回执行机磁盘，命中即直接重放，**跳过大模型调用**——省 token、提速、还更稳定（不受模型输出波动影响）；
2. **AI 兜底**：缓存失效或未命中时自动切换回 AI 视觉识别，准确性不受影响；
3. **动态内容精确到步骤级禁缓存**：验证码、短信码、随机数、当前日期等易变内容，通过 **`[动态]` 前缀标记**（或关键词自动识别：验证码/captcha/滑块/点选/随机值/时间戳/uuid…）只对**该步骤**设 `cacheable: false`，而不是牺牲整条用例的缓存加速——这是"验证码永远会变，但查询按钮不会"的现实主义设计。

用例缓存的"真相源"在执行机磁盘，平台 DB 缺失时自动回源拉取，执行后增量回传——分布式场景缓存不丢。

### 4.5 Chrome 插件：真实浏览器里的"录制式"用例生产闭环 ⭐

安装测试用例可视化插件后（平台内有下载与图文安装指引）：

1. **浏览器内 AI 逐步执行**：在侧边栏输入自然语言，AI 在你当前真实页面上一步步执行，每步带勾选框；
2. **智能导出**：默认排除执行失败的步骤、可手动勾选有效步骤，拼接成 NLP；
3. **一键推送中台**：点一下就"自动确保项目/目录/登录方式就绪 → 创建用例 → 触发执行"，全程一个接口完成；
4. **事件录制器**：后台监听你的点击/输入/滚动操作辅助生成步骤描述；
5. **文件下载断言**：插件内即可验证下载的 docx/xlsx 内容。

> 一句话：**"真实浏览器里跑一遍 → 勾选有效步骤 → 自动入库并执行"**，从手工探索到自动化沉淀只需两分钟。

### 4.6 失败不瞎猜：报告页内的排障闭环 ⭐

这是区别于"只告诉你挂了"的普通测试平台的关键能力：

- **Midscene HTML 视觉报告**：精确到**每一步的截图、元素定位过程、Agent 回放**——AI 为什么点了那个按钮，报告里看得明明白白；
- **API 报文观测**：执行中拦截全部 fetch/xhr 报文（含请求/响应 body）随报告归档，报告页直接查看报文明细；
- **SkyWalking 链路染色**：每个测试请求自动注入 `sw8` trace 头，报告页可查看 **Trace 拓扑图 + 接口日志**（Service/Endpoint/SQL/Span 详情），前后端联调排障不用再互相甩日志；
- **AI 根因分析（RCA）**：用例失败时，自动收集错误 API 报文 + Trace 日志构造 Prompt，**流式输出思考过程**给出根因推断，结果缓存、二次查看秒回；
- **批量合并报告**：批量执行完成后自动把多次执行合并为一个 HTML 总报告（含 testId/状态/耗时），5 秒轮询自动触发、幂等防重。

### 4.7 执行链路的工程保障（测试人员可感知的部分）

- **并发与排队**：Worker 池并发执行（默认并发 3），排队时能看到自己的排队位置；支持内存 / Redis 两种队列模式；
- **实时进度**：SSE / WebSocket 双通道推送逐步执行进度（"执行步骤： 输入 xxx"）；
- **可取消**：排队中的直接移除，运行中的发取消信号；调试模式也支持中途取消；
- **调试模式**：**不落库、不建用例**的即写即跑草稿执行——写步骤时随手验证，满意了再保存；
- **多模型 AI 配置**：OpenAI / Claude / Gemini / 豆包 / DeepSeek / Qwen 等家族任选，自定义 Base URL + Key，按效果与预算灵活切换（Key 脱敏显示）；
- **内网友好细节**：自动忽略 HTTPS 自签证书错误（金融内网常见）、优先使用系统 Chrome；
- **数据看板**：成功率对比（绿/黄/红分级）、近 7 日趋势、告警阈值可配。

## 五、一个用例的完整生命周期（演示串联脚本）

建议按以下顺序现场演示，覆盖全部亮点：

1. **配置登录方式**（cas/local + 补充步骤选"图形验证码"动态值类型）→ 观察自动生成 `[动态]` 标记；
2. **NLP 创建用例**：输入口语化步骤 → 看流式 AI 思考 + YAML 生成 → 表单/YAML 双向同步；
3. **预览最终脚本**：确认登录 YAML 注入正确、无重复登录 task；
4. **首次执行**：观察登录阶段真实执行、逐步进度推送、登录方式状态变为 `cached`；
5. **二次执行**：观察登录缓存命中提速；
6. **故意制造失败**（改错断言）→ 打开报告：
   - 看步骤级截图与 Agent 回放；
   - 看 API 报文明细；
   - 看 SkyWalking Trace 拓扑；
   - 点"根因分析"看 AI 流式推断；
7. **插件演示**：浏览器内跑步骤 → 勾选 → 一键推平台执行；
8. **批量执行**：选中多用例 → 等合并报告生成 → 打开总报告。

## 六、实践建议（常见问题速答）

**Q1：NLP 模式和 YAML 模式怎么选？**
- 探索新场景、简单流程 → NLP，写得快；
- 需要精确控制（文件操作、特殊等待、复杂断言）→ YAML；
- 两者可随时互转，NLP 改动自动同步 YAML。

**Q2：有验证码的系统怎么办？**
- 把验证码步骤写进登录方式"补充步骤"，动态值类型选"图形验证码"，平台自动 `[动态]` 标记 + `cacheable: false`；
- 其余登录步骤照常享受缓存，验证码步骤每次走 AI 现场识别。

**Q3：用例执行突然变慢/变快了？**
- 变快：大概率命中了缓存（登录缓存 / 用例 plan 缓存）；
- 变慢：缓存可能因页面改版失效，回退 AI 视觉识别；若持续失败，说明页面结构变化较大，重新生成脚本即可。

**Q4：AI 生成结果不稳定？**
- 平台生成温度已固定 0.1；若仍偶发偏差，优先改 NLP 描述为更具体的元素名称（"点击顶部导航栏的用户管理菜单"优于"点击菜单"）；
- 可在 AI 配置页切换更适配的模型。

**Q5：登录方式改密码了会不会用旧缓存？**
- 不会。任何登录核心信息变更自动把缓存状态重置为 uncached，下次执行重新登录重建。

## 七、总结：记住五大杀手锏

1. **中文大白话 → 可执行脚本**：NLP 标准化 + 流式 AI 生成 YAML，看得到 AI 的思考过程，零代码门槛；
2. **登录一次、全项目复用**：独立登录缓存 + uncached/cached 状态回调 + 变更自动失效；
3. **缓存优先 + AI 兜底 + 动态步骤精确禁缓存**：`[动态]` 标记只牺牲易变步骤，其余步骤重放缓存——又快又准又省 token；
4. **插件录制式用例生产闭环**：真实浏览器 AI 逐步执行 → 勾选有效步骤 → 一键入库并执行；
5. **失败不瞎猜**：步骤级视觉报告 + API 报文 + SkyWalking Trace 拓扑 + AI 流式根因分析，一条报告页内闭环排障。

> 最后回到平台理念：**"单个 case 微小提升，批量场景大幅提升"**——每条用例省下几秒登录、几次模型调用，几百条回归跑起来，就是质变。
