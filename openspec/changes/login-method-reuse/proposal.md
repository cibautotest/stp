# 登录方式复用（Login Method Reuse）

## 变更概述

将测试登录步骤抽象为**按项目维度的"登录方式"资产**，支持免登录 / CAS 登录 / 本地登录三种类型、多账号角色切换；执行用例时先以**独立缓存 ID**（`login_{methodId}`）执行登录阶段（首次 AI 生成缓存、后续命中缓存），再在同一浏览器上下文继续执行用例主体（`caseId` 缓存），实现登录步骤跨用例复用与提速。

## 背景与问题

当前每个用例把登录步骤直接写进 YAML，缓存绑定在 `caseId` 上——每个用例都要各自由 AI 重新生成登录步骤（慢、费 token、且同一登录流程重复执行）。项目中存在三类登录情况：免登录、CAS 登录（账号密码）、本地登录（账号密码 + 图形验证码/短信验证码/弹窗），且同一登录方式下可能有多个账号角色。

## 目标

1. **登录方式资产**（按项目维度）：
   - 三种类型：`none`（免登录）、`cas`（CAS 登录）、`local`（本地登录）
   - 字段：名称、登录网址、账号、密码（加密）、角色名、步骤 NLP、生成的 yaml_script、缓存状态（未缓存/已缓存）
   - 同类型支持多角色；用例可切换角色，默认记住上次执行的角色
2. **创建用例页**：选择项目下拉框下方、NLP/YAML 模块上方新增"登录方式"区块；**必选其一，未选不能执行**；已执行过缓存的方式标记"已执行过，有缓存"，否则"未缓存"
3. **执行语义**：登录阶段（AI 首次或缓存）完成后**不关闭浏览器**，在同一 page 上继续执行后续步骤
4. **插件导出弹窗**：支持选择/创建登录方式并随用例同步
5. **NLP 标准化 prompt**：`[动态]` 标记规则 + `cacheable: false` 生成规则（动态步骤：日期、图形验证码、随机值等永不缓存）

## 非目标

- 不做登录方式的跨项目共享
- 不做登录失败的自动重试编排（失败仍按现有报告呈现）
- 密码加密存储不做 KMS 级别，复用现有对称/散列体系即可

## 验收标准

1. 创建用例页未选登录方式时执行按钮不可用/报错；选免登录后可直接走后续流程
2. CAS/本地登录方式可创建、可选择、可切换角色，默认记住上次角色；缓存状态标记正确
3. 执行含登录方式的用例：登录阶段与用例主体在同一浏览器会话中连续执行；第二次执行登录阶段明显提速（缓存命中）
4. 插件导出用例时可选择/创建登录方式，同步后平台用例带 login_method_id
5. 动态步骤（`[动态]` 标记）生成的 YAML 带 `cacheable: false`
