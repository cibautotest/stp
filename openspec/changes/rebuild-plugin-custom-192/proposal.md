# 以 1.92_0 为基底重建定制插件 + 执行引擎 SDK 对齐 1.12.2

## 变更概述

以官方原版 `1.92_0/` 为干净基底，重建"测试用例可视化插件"的全部定制能力，修复此前定制版（1.92_old）的三个问题，并新增两项功能；同时将 execute-service 的 Midscene SDK 从 1.9.2 升级到 1.12.2（与插件内置 SDK 版本对齐）。

## 背景与问题

### 已定位的三个问题
1. **版本号不可见**：旧定制版移植的"隐藏版本号"脚本把 `Midscene.js version: 1.92` 与 `SDK v1.12.2` 文本节点全部隐藏，用户无法在界面确认版本
2. **项目列表不同步**：用户实际打开的侧边栏来自 1.52 导入包（`size=500` 被后端 `@Max(100)` 校验拒绝 → 列表为空），同名扩展混淆所致；后端接口与数据链路实测正常
3. **qwen3 模型验证失败**：官方 bundle 合法 family 枚举为 `qwen3-vl`/`qwen3-vl-plus`，裸 `qwen3` 不在列表——配置值问题，非定制层问题（交付时需在说明中提示）

### 附带发现
插件 1.92 内置 SDK 为 **1.12.2**（bundle 原文 `(SDK v1.12.2)`，npm 上 1.12.2/1.12.3 存在）。execute-service 当前锁定 1.9.2 是此前误判（原 `^1.12.1` 并非笔误），需升级到 1.12.2 对齐。

## 目标

1. **新版定制插件**（新目录，保留 1.92_0 原版备份）：
   - 用户登录（平台账号密码，token 持久化与静默恢复）
   - 选择/创建项目（有权限项目列表 size=100，服务端覆盖式刷新）
   - 智能选择步骤：失败步骤默认不选（可手动加回）
   - 一键同步平台（`POST /api/platform/execute/create-and-execute`）
   - 界面显示定制版本标识「测试用例可视化插件 v1.92」，不再隐藏官方版本号
   - **已生成用例标记**（按项目维度）：之前导出过的步骤默认不勾选，并在步骤行显示小标注明所属用例名
   - **随机数按钮**：指定位数生成随机数并自动插入聊天输入框（触发 React input 事件）
2. **execute-service 升级**：`@midscene/core`、`@midscene/web` → `1.12.2`，tsc 编译验证

## 非目标

- 不修改官方 bundle（static/js、worker.js 等）
- 不删除 `Midscene.js 1.52/`、`Midscene.js 1.92_old/`、`1.92_0/` 目录（保留备份，由用户决定是否清理）
- 不修改后端（此前的 token + CORS 改动已满足插件需求）
- 不处理 1.52 导入包的卸载（提示用户手动操作）

## 影响范围

| 模块 | 变更 |
|------|------|
| 新插件目录 `测试用例可视化插件-v1.92/` | 复制 1.92_0 + manifest 改名去商店标识 + index.html 注入定制块 + scripts/auth.js、export-test-case.js |
| `execute-service/package.json` | @midscene/* → 1.12.2 |

## 验收标准

1. 插件侧边栏显示定制版本标识与官方版本号（不再隐藏）
2. 登录后可拉取有权限项目列表；可创建项目
3. 导出弹窗中：失败步骤红色 ✗ 默认不选；已生成过的步骤带黄色"已生成: 用例名"小标、默认不选；两者均可手动改选
4. 随机数按钮可指定位数生成并填入聊天输入框
5. 一键同步后平台出现用例并开始执行；该次勾选的步骤被记录为"已生成"
6. execute-service `tsc` 编译通过，@midscene 实际解析为 1.12.2
