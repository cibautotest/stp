# Design: 平台上手体验与文档标准化

> **关联 PRD**: [proposal.md](./proposal.md)

---

## Context

### 目标受众

| 角色 | 需求 | 关注点 |
|------|------|--------|
| 新开发者 | 快速启动项目开始二次开发 | 启动命令、技术栈、项目结构、API 文档 |
| 测试人员 | 了解平台能做什么、怎么用 | 功能介绍、工作流程、登录账号 |
| 零基础人员 | 理解整个平台的价值命题 | 项目简介、核心功能、架构概览 |

### 当前 README 问题

```
当前结构：                      问题：
├── 架构说明（6 行）             ← 未经解释直接进入技术细节
├── 快速开始                     ← 启动命令与脚本不一致
│   ├── 环境要求                 ← OK
│   ├── 本地开发                 ← mvn 启动 vs .bat 脚本冲突
│   ├── Docker Compose 部署      ← OK
├── 服务端口                     ← OK
├── API 文档                     ← OK
├── 技术栈（9 行简表）            ← 缺少关键组件说明
├── 项目结构（15 行）             ← 缺少前端结构
└── License                      ← OK
```

缺失的关键信息：
- 不知道平台「是什么」和「能干什么」
- 不知道「怎么用」（从登录到完成测试的全流程）
- 不知道「默认账号」
- 前端项目结构完全不可见

## Decisions

### Decision 1: README 章节顺序

**选择：从上到下按"认知→理解→行动→参考"的递进逻辑排列**

```
新增：                          保留：
├── 项目简介（概念层）           ├── 快速开始（保留，启动命令已更新）
├── 核心功能（理解层）           ├── 服务端口（保留）
├── 整体架构（理解层）           ├── API 文档（保留）
├── 工作流程（行动引导）         ├── 技术栈（增强）
├── 快速开始（实操层）           ├── 项目结构（增强）
│   ├── 环境要求                 └── License（保留）
│   ├── 本地开发（已更新）
│   ├── 访问地址
│   ├── 默认账号（新增）
│   ├── 插件更新说明（新增）
│   └── Docker Compose 部署
```

**理由**：零基础读者从顶部往下读，依次获得"这是什么→能做什么→怎么做的→动手试试"的完整体验。

### Decision 2: 架构图形式

**选择：ASCII 字符画**（非 Mermaid 流程图）

**理由**：ASCII 图在任何 Markdown 渲染器（GitHub/GitLab/IDE/终端）中一致显示，不依赖 Mermaid.js 运行时。

```
┌─────────────────────────────┐
│     前端层                   │
├─────────────────────────────┤
│     网关                     │
├─────────────────────────────┤
│     服务注册                 │
├───────────┬─────────────────┤
│ 业务服务  │ 执行引擎          │
├───────────┴─────────────────┤
│     数据存储                 │
└─────────────────────────────┘
```

### Decision 3: 技术栈表格扩展

**选择：四列分层级格式**（层级/组件/技术选型/版本）

原格式 9 行：
```
| 组件 | 技术选型 | 版本 |
```

新格式 22 行：
```
| 层级 | 组件 | 技术选型 | 版本 |
```

新增了：CodeMirror 6, Druid, Knife4j, Spring Security + JWT, OpenFeign, Fastify 等关键依赖。

**理由**：开发者需要知道具体依赖才能排查问题，22 行表格可通过 IDE 的 `[TOC]` 或 `Ctrl+F` 快速定位。

### Decision 4: pnpm 作为默认包管理器

**选择：所有 README 统一使用 `pnpm`**

| 文件 | 变更前 | 变更后 |
|------|--------|--------|
| 主 README | 混合 npm/pnpm | 统一 pnpm |
| frontend/README.md | npm | pnpm |
| execute-service/README.md | npm | pnpm |

**理由**：项目根目录存在 `pnpm-lock.yaml`，实际开发使用 pnpm，文档应与实际一致。

### Decision 5: 启动命令简化

**选择：用 `.\restart-backend.bat` 替代逐模块 mvn 启动**

```
变更前（5 条命令）：                  变更后（1 条命令）：
cd backend                            .\restart-backend.bat
mvn clean install
cd eureka-server && mvn spring-boot:run
cd gateway-service && mvn spring-boot:run
cd platform-service && mvn spring-boot:run
```

**理由**：项目根目录已提供 `restart-backend.bat` 封装脚本，README 应指向最简路径。开发者如需了解细节可打开 .bat 文件查看。

---

## Non-Decisions (未改变的设计)

- 不修改 API 文档格式
- 不修改服务端口表格
- 不改变 Docker Compose 部署方式
- 不引入新的文档生成工具（如 Docusaurus）
